# BartalBot (`bartal-bot`)

> **BartalBot** — Telegram-бот для автоматизации согласования, регистрации и оплаты первичных документов (счета, акты) по проектам с ролевым контролем доступа и интеграцией с Excel.

---

## 🚀 Быстрая установка (Quick Start)

Развертывание бота на сервере (Ubuntu/Debian/RHEL/CentOS) в одну команду:

```bash
git clone https://github.com/MBober12/bartal-bot.git
cd bartal-bot
chmod +x install.sh scripts/*.sh
sudo ./install.sh
```

### Что сделает скрипт установки:
1. Проверит и при необходимости установит OpenJDK 17, Maven, Git.
2. Интерактивно запросит токен Telegram-бота и ID первого администратора.
3. Соберет проект (`mvn clean package -DskipTests`) в оптимизированный jar-пакет `bartal-bot.jar`.
4. Развернет файлы в каталог `/opt/bartal-bot/`.
5. Создаст защищенную конфигурацию `config.properties` (права `600`).
6. Зарегистрирует и запустит systemd-службу `bartal-bot` (с автозапуском при перезагрузке).
7. Скопирует CLI-скрипты администрирования в `/opt/bartal-bot/scripts/`.

## 💡 О проекте и его сути

В проектной деятельности (строительство, производство, субподряды) часто возникает хаос при передаче документов: исполнители с площадки присылают фото счетов или актов в разрозненные чаты, документы теряются, руководители забывают согласовать, а бухгалтерия не знает, кому и за какой проект выставлен счет.

**BartalBot** решает эту проблему через **строгий поэтапный пайплайн согласования (`Stage`)**:
1. **Пользователь (`USER`)** загружает документ (фото/PDF счета или акта), указывает комментарий и привязывает его к конкретному проекту.
2. **Утверждающий (`APPROVER`)** (ГИП, руководитель проекта) получает уведомление в Telegram с инлайн-кнопками, проверяет документ и принимает решение: согласовать сразу на оплату, согласовать с обязательной регистрацией либо отклонить с указанием причины.
3. **Регистратор (`REGISTRAR`)** (бухгалтерия/делопроизводство) вносит реквизиты документа во внутренний учет и подтверждает регистрацию.
4. **Получатель / Финансист (`RECEIVER`)** видит полностью готовый к оплате документ и отмечает факт оплаты/исполнения.
5. На каждом этапе бот автоматически отправляет регулярные напоминания ответственным лицам, пока документ не сдвинется по статусу.

## 🔄 Жизненный цикл документа (`Stage`)

```
   [Пользователь]
         │
         ▼ (Загрузка счета / акта)
     SUBMITTED
         │
         ▼
     ACCEPTING  ──(Отклонен)──► BLOCKED_AT_ACCEPTANCE
         │
    ┌────┴────────────────────────┐
    │ (Требуется регистрация)      │ (Без регистрации)
    ▼                             ▼
ACCEPTED_WITH_REG            ACCEPTED_NO_REG
    │                             │
    ▼                             │
REGISTERING                       │
    │                             │
    ├──(Отклонен)─► BLOCKED       │
    ▼                             │
REGISTERED                        │
    │                             │
    └──────────────┬──────────────┘
                   │
                   ▼
                PAYING ──(Отклонен)──► BLOCKED_AT_PAYMENT
                   │
                   ▼
                 PAID (Оплачен / Завершен)
```

## 👥 Роли в системе

| Роль | В коде (`Role`) | Обязанности в процессе |
|---|---|---|
| **Пользователь** | `USER` | Загружает счета и акты по проектам, отслеживает статус своих документов |
| **Утверждающий** | `APPROVER` | Согласовывает переданные документы или отклоняет их с указанием причины |
| **Регистратор** | `REGISTRAR` | Регистрирует согласованные документы в корпоративном учете |
| **Получатель** | `RECEIVER` | Принимает к оплате и подтверждает проведение платежа |
| **Администратор**| `ADMIN` | Управляет пользователями, правами, псевдонимами, загружает реестры проектов из Excel |

```
.

    ├── apiClient/                   # Слой взаимодействия с Telegram Bot API
    │   ├── TelegramApiClient.java   # HTTP-клиент (отправка сообщений, файлов, инлайн-кнопок, удаление/изменение)

    │   └── TelegramApiException.java# Кастомные исключения API Telegram
    │
    ├── handler/                     # Обработчики входящих событий от пользователей
    │   ├── TextHandler.java         # Обработка текстовых команд меню, FSM-состояний пользователей
    │   ├── CallbackHandler.java     # Обработка нажатий Inline-кнопок («Согласовать», «Отклонить», «Оплатить»)
    │   ├── FileHandler.java         # Прием документов и фотографий (счетов/актов) от пользователей

    │   └── BirthdayHandler.java     # Дополнительные сервисные нотификации
    │
    ├── keyboard/                    # Генераторы интерфейса Telegram
    │   └── KeyboardBuilder.java     # Reply- и Inline-клавиатуры для каждого шага и роли
    │
    ├── model/                       # Доменные модели и сущности
    │   ├── Paper.java               # Первичный документ: тип (счет/акт), файл, проект, таймстемпы, согласователи
    │   ├── Project.java             # Проект (шифр, название, закрепленные ответственные)
    │   ├── User.java                # Пользователь (chatId, псевдоним, список ролей Set<Role>, FSM-состояние)
    │   ├── Stage.java               # Этапы жизненного цикла документа (SUBMITTED -> PAID)
    │   ├── Role.java                # Роли (USER, ADMIN, APPROVER, REGISTRAR, RECEIVER)
    │   ├── DocType.java             # Тип документа (INVOICE, ACT)
    │   ├── UserState.java           # Конечный автомат (FSM) состояний диалога
    │   ├── DocResult.java / TextResult # DTO результатов обработки команд
    │   └── Keyboard.java / Button.java # Абстракции элементов интерфейса
    │
    ├── repository/                  # Слой доступа к данным (SQLite JDBC)
    │   ├── DbInitializer.java       # DDL-миграции и создание таблиц (users, papers, projects, reminders)
```

## 🖥 CLI-утилиты для обслуживания (`scripts/`)

Вспомогательные скрипты находятся в каталоге `scripts/` (а также в `/opt/bartal-bot/scripts/` после установки):

### ➕ Добавление / Повышение администратора (`scripts/add-admin.sh`)
Выдает пользователю права администратора (`isAdmin=1`) и обычного пользователя (`isUser=1`):
```bash
# Интерактивный режим:
./scripts/add-admin.sh

# Или аргументами [chatId] [Имя]:
./scripts/add-admin.sh 987654321 "Главный Инженер"
```

### ➖ Снятие прав администратора (`scripts/remove-admin.sh`)
Безопасно переводит админа в статус обычного пользователя:
```bash
./scripts/remove-admin.sh 987654321
```
*(Скрипт защищен от удаления последнего оставшегося администратора).*

### 🗑 Деинсталляция бота (`scripts/uninstall.sh`)
```bash
# Интерактивное меню (сохранить БД, сделать бэкап или удалить всё):
sudo ./scripts/uninstall.sh

# Быстрые ключи:
sudo ./scripts/uninstall.sh --purge      # Полное удаление службы и каталога /opt/bartal-bot
sudo ./uninstall.sh --keep-data  # Удалить службу и jar, сохранив БД и настройки
sudo ./scripts/uninstall.sh --backup     # Создать архив /opt/bartal-bot-backup-*.tar.gz и удалить каталог
```

## ⚙️ Ручная сборка и запуск

Если вы хотите запустить бота вручную без systemd:

1. **Сборка jar-пакета:**
   ```bash
   mvn clean package -DskipTests
   ```
   Собранный uber-jar появится по пути: `target/bartal-bot.jar`.

2. **Создание конфигурации `config.properties`:**
   ```properties
   bot.token=123456789:ABCdefGHIjklMNOpqrsTUVwxyz
   admin.chatId=123456789
   db.path=bartal-bot.db
   projects.file=projects.xlsx
   ```

3. **Запуск:**
   ```bash
   java -jar target/bartal-bot.jar
   ```

```bash
sudo systemctl status bartal-bot        # Статус службы
sudo journalctl -u bartal-bot -f        # Просмотр логов в реальном времени
sudo systemctl restart bartal-bot       # Перезапуск службы
sudo systemctl stop bartal-bot          # Остановка службы
```
